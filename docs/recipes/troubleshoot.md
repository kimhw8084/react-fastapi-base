# Troubleshooting

A 503 readiness response means configuration, file availability or migration heads need investigation. Check server logs by request ID; do not return raw SQL/paths/stacks to the browser. A 401 identity error means the company variable is absent/invalid; never substitute admin. A 403 can be tenant, permission, CSRF or origin failure; refresh bootstrap for a new token and verify server policy.

A 409 is a real conflict: fetch the current revision and reconcile changes. Retrying a create/import with the same idempotency key is appropriate when the response was uncertain; inventing a new key can duplicate a successful prior action. A blank table must not mask a failed request.

For routing, open health and bootstrap through the actual company browser path. An HTML login redirect is not JSON API success. Runtime API base is origin-only. The Node static server intentionally has no /api proxy. Inspect network/CORS/ingress without copying cookies or environment secrets into support reports.

Blocked frontend checks mean install/lock/build proof is missing, not that TypeScript passed. Review evidence/verification logs and the remaining scope ledger before accepting the artifact.
